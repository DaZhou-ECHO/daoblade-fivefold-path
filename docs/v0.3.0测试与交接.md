> 本文记录 `work/v0.3.0-cultivation-worlds` 候选分支的实际执行情况。尚未合并到 `develop` 或 `main`，也未创建正式版本标签。

## 本轮检查

- 旧存档可补齐空出战栏，原有镶嵌不被迁移过程修改。
- 账号各自读取存档；登录存档写入需要 CSRF 和版本号；第二窗口更新后旧窗口返回 409。重置操作同样检查版本号。
- 直接提交未达到修炼等级的外层珠子会被拒绝；已镶珠仍不可取下、替换或改五行品阶；出战技能必须已经学会且同种栏位不重复。
- 所有八卦主动技能能施放，Q/E 各自冷却；五种主修表现、五境布局、祭坛可达性和非火境敌人前摇由 Node 回归覆盖。
- 浏览器实测：本机隔离数据库的首页、五行秘境选择、火境进入和战斗画面正常显示，人物位于地面，火境远景、敌人、HUD、触屏操作均可见。浏览器实测**没有**覆盖完整通关和全部账号交互。

## 实际执行命令与结果

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider --basetemp D:\acode\codex\pytest-daoblade-v03
node --check static/js/game.js
node --test tests/combat.test.cjs
```

记录结果：Python **27 passed**；Node **12 passed / 0 failed**；JavaScript 语法检查通过。第一次不指定 `--basetemp` 运行 pytest 时，受限沙箱内的系统临时目录不可写，出现 8 个测试准备阶段错误；改用可写临时目录后所有测试通过。该错误不是业务断言失败，普通 Windows 环境通常无需指定 `--basetemp`。若代码继续改动，应重新执行并更新本段数字。

## 手工评测建议

1. 升级前备份 `instance/daoblade.sqlite3`，在新分支启动本地 Flask。
2. 用旧游客存档打开页面，确认灵珠、五行和修行图仍在；注册新账号，使用“导入游客存档”，确认账号已有数据时不会覆盖。
3. 用两个浏览器窗口登录同一账号，分别变更存档，确认落后窗口提示冲突且服务器数据没有被覆盖。
4. 依次体验五境，从主路到首领，测试两个高台祭坛和危险区；测试触屏按钮的可操作性。
5. 先修出一层心法，升到二级后镶第二层；升第二层珠至三级后镶第三层。装备两技能两心法，关外换装，再进入战斗验证 Q/E 和心法差异。

## 已知风险与后续工作

- 本地用户系统面向可信测试环境；Web 战斗由客户端模拟，不能抵御故意伪造的战斗结算或资源数据。
- 目前靠 SQLite 单机保存；没有联机同步、账号找回、管理员审核后台，也没有自动数据库备份。
- 五境布局为固定地图，资源为程序绘制，动作帧、首领阶段、设备兼容性和数值平衡仍需人工测试。
- 高并发、大量在线用户、长时间自动闯关和公开部署尚未验证。

下一位开发者先从本候选分支拉取，运行上述自动测试并完成手工评测，再决定修正、PR 合并或继续新一轮。勿将候选分支直接标记为正式发布。
