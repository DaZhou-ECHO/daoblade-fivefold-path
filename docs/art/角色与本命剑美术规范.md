# 角色与本命剑美术规范

状态：2026-10-20 接续开发，`automation/character-art` 候选分支，代码基线 `6b06fed`。保留首轮角色身份与原画，本轮补齐统一的程序战斗姿态。项目中未找到《261020角色.txt》原文件；依据现有规范及用户本轮要求实施，不推定缺失文件的额外内容。

## 角色身份与文化边界

同一位青年江湖剑客：黑发束发、赤色发带、深靛交领短袍、浅色内领、布腰带、深色裤与布靴。以轻便清晰的战斗剪影为准。角色服装是原创修仙装束，未宣称复原某时代或某派道教冠服。文化依据与原创部分见《角色文化取材表》。

素材为内置 imagegen 生成的原创角色动作原画，经人工选定分区和锚点，再用 Pillow 清理透明毛边、裁切、最近邻缩小并统一调色板。它属于 **AI 辅助像素精灵**，不声称是专业美术师纯手绘逐帧作品。源图锁定于 `docs/art/sources/`，下一轮沿用身份与参考，不重新随机生成角色。

## 已交付资源

| 资源 | 帧数 | 帧容器/整图 | 帧率 | 脚底/旋转点 |
|---|---:|---|---:|---|
| `static/sprites/player/base/idle.png` | 4 | 64×96 / 256×96 | 6 FPS | 每帧 `(32,90)` |
| `static/sprites/player/actions/run.png` | 8 | 64×96 / 512×96 | 12 FPS | 每帧 `(32,90)` |
| `static/sprites/weapons/base/jian.png` | 1 | 20×64 | 随角色 | `manifest.json` 的 `weapon.grip` |

所有文件具有真实 RGBA 透明通道，无棋盘背景；人物共用 32 色调色板，剑为 16 色。脚底锚点是世界基准，跑动腾空相位的脚可以离开此线，不能为了贴线把整个人向下拉。每帧握剑点及旋转角在 `static/sprites/player/manifest.json` 中记录。剑柄与手点重合，手指小块在剑之上重绘。

角色正面标准为朝右；左右翻转围绕脚底中心。实际绘制左上角为 `(round(x+w/2)-32, round(y+h)-90)`。玩家碰撞箱维持 38×70；不改变伤害、无敌帧、攻击距离或实体坐标。待机跑动使用 `animTime`，战斗姿态读取已有动作剩余时间，暂停和顿帧时随战斗停止；不对 PNG 再套旧角色的整身 bob。关闭 Canvas 平滑。

`character-art.js` 负责验证、缓存和显示素材。待机/跑动图片与剑全部成功加载且尺寸匹配后才启用；网络、JSON、图片、模块缺省或实际 `drawImage` 异常均使用 `drawPlayerCanvas`。绘图异常完整恢复嵌套 Canvas 状态并关闭损坏的图片路径，避免每帧重复抛错。

三段劈砍、格挡/完美格挡、剑气/主动技能、闪避、跳跃/下落、受击、战败都使用同一人物及 `jian.png`，不再因正常动作切换回旧人物。程序动作以 idle 第 0 帧分为 0～65 行上身、66～95 行下身，上身绕腰部倾斜，腿部保持脚底基准；剑与手指跟随上身变换，独立剑仍绕同一个 grip 旋转。三剑分别下斩、反向上斩与大幅重斩，按真实 `slash/slashDuration` 进度蓄势、挥出、回位；剑光随同一角度绘制。此方案是可运行的最小战斗美术阶段，没有新增攻击 PNG。

限制：上臂、腿部尚无专用逐帧动作，空中姿势暂以倾斜区分上升/下落，战败为定格，闪避没有完整残影动画；跑动进入固定战斗站姿仍需进一步人工评测衔接。没有声称完成全部专用美术。浏览器已查看练功场与第三剑双向中段；自动测试覆盖三连击、其他动作触发、脚底/握点和收招。完整五境通关、全部动作逐帧人工审查尚未验证。截图见 `combat-slash3-left.png`。

## 后续五行服章接口约定（尚未实现）

最终外观：固定本体 + 主元素服装/本命剑 + 副元素配饰 + 八卦位置 + 修行深度 + 战斗特效。`futureLayers` 只是清单中的接续声明，不代表已交付图层。

主元素轮廓：金月白银灰、线条收束；木苍青黛绿、曲直纹理；水玄黑深蓝、下垂衣摆；火朱赤绛红、向上衣缘；土赭黄黄玉、稳定腰封。副元素仅作用于簪、剑穗、缠绳、腰佩、衣缘、护腕等局部，约占视觉面积 15%～20%。该比例是美术规范，不是典籍规定。

八卦位置：乾头、坤腹、震足、巽股侧摆、坎耳、离目、艮手、兑口邻近衣领。三层成长依次为显纹、成器、化象；后期通过动态法象表达成长，避免配饰越堆越大。

当前代码在五行修为并列时保持主副未定，未记录可靠镶嵌序号；用户计划要求“先镶者优先”。本轮不改此战斗规则。后续须同时设计镶嵌序号与旧档迁移后再实现，不能靠对象遍历顺序伪造历史。游戏传入本次战斗 `stats.primary` 的特效颜色；主副服装、剑形、副饰及八卦深度外观仍未接入，基础人物不按五行换装。

## 构建与预览

游戏运行不需要 Pillow；整理或检查美术时使用 `requirements-art.txt`。

```powershell
python -m pip install -r requirements-art.txt
python tools/prepare_character_art.py --sheet docs/art/sources/character-v1.png --sword docs/art/sources/jian-v1.png
python tools/check_character_art.py
```

在 Flask 服务地址后打开 `/static/character-preview.html`，可检查原始尺寸/三倍预览、左右方向、逐帧、五种背景和锚点。`docs/art/角色帧检查.png` 提供十二帧双向接触表；原画提示词记录见《角色原画提示词》。这张检查图不替代实机测试。
