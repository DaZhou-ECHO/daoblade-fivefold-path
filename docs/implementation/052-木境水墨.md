## 二、实施方式

### 1. 只替换木境资源，不改校验与帧时序

- 输出文件名与尺寸全部保持原值（768×144、768×96、128×32、256×96、各族帧尺寸不变），因此 `world-art-assets.js` 的清单校验、`scene-art.js`/`enemy-art.js` 的取样坐标、碰撞与攻击时序**都不需要改**。
- 原始素材保留在 [木境原始资源快照](../art/wood-v1-legacy/)，同时作为重建输入：`tools/build_wood_ink_art.py` 每次从快照读、只写 `static/sprites/world-v1/wood-*.png`，重复运行结果一致（脚本内有文件名前缀断言）。
- 调色板回到原上限：普通怪 31 色、Boss 47 色、场景 64 色；透明通道与帧格位置不变。

### 2. 水墨是“环境层”，不是滤镜

- 远景：一道低对比墨山脊 + 纸色天光 + 两缕湿边薄雾 + 纸纹。原画的瀑布、塔与树冠保持可见。
- 中景：压暗一档并加入粗枝干、藤帘与根系拱，形成“近一层”的剪影。
- 地形/道具：苔冠提亮保证平台可读；剑碑改为纸白石面 + 墨裂 + 朱印，作为木境地标。
- 怪物：外轮廓压成墨线，左上边缘加纸白受光，叶簇由黄绿转向苔青，树皮只轻提亮度——目标是“在深绿天幕下能一眼看出轮廓”。

### 3. Boss 技能的水墨表现

新增 [wood-ink.js](../../static/js/wood-ink.js)，只在 `realm === "wood"` 且目标是 Boss 时介入：

| 阶段 | 表现 | 与规则的关系 |
|---|---|---|
| 前摇 `windup` | 脚下墨池随进度晕开，面朝方向出现短笔触 | 纯装饰；真正的预警仍是原有黄色标记 |
| 攻击 `strike` | 沿朝向画一笔干笔弧线与墨点 | 不宣称、也不改变攻击范围 |
| 受击 `hurt` | 五个固定角度的溅墨点 | 由既有受击状态驱动，不新增事件 |

实现方式是**包装**而不是改写：`wood-ink.js` 用子类包装 `DaoBladeSceneArt.Renderer` 与 `DaoBladeEnemyArt.Renderer`，先调用原方法，成功后再叠加木境表现。异常只会让本层失效一次，原渲染与战斗继续。

### 4. 共享文件为何必须动

范围要求“未经确认不改共享模块”。本轮只碰了两处，均无法用纯资源方案替代：

| 文件 | 改动 | 为什么必须 | 风险与兜底 |
|---|---|---|---|
| `templates/index.html` | 在 `scene-art.js` 之后加载 `wood-ink.js`（一行） | 浏览器需要执行这层表现；没有其他脚本注入入口 | 脚本缺失时游戏照常运行（`game.js` 只读 `globalThis`） |
| `static/js/wood-ink.js`（新增） | 包装两个 Renderer | 现有渲染管线没有“按五行挂载后处理”的扩展点 | 只在 wood 生效；异常自禁用；`node --test` 覆盖非木境、待机、普通怪与异常分支 |

`game.js`、`level-definitions.js`、`enemy-art.js`、`scene-art.js`、战斗数值、AI、碰撞、存档与 UI **均未修改**。

## 四、边界与未完成

- 画面证据分两层：**离线合成帧**（按 `game.js` 的绘制顺序与参数复刻）与**真实 Chrome 渲染**（`tools/check_wood_ink_browser.py` 打开世界美术预览页，50 张 PNG 全部加载、异常 0）。登录后进入正式关卡的整局实玩仍未做，文字与截图都不把它说成已完成。
- Boss 水墨只覆盖现有三个可读阶段，没有新增技能、无敌帧、伤害或击退；`山水留白`、`枯荣转换` 两个原型因需要改动 Boss 状态机，本轮未做。
- 怪物动作仍是“同一张原画的按高度加权变形 + 关键行加强”，没有手绘关键帧图集；这一点沿用 049 的已知限制，未把它写成“已实现序列帧动画”。本轮把木灵刀卫的黄绿描边压掉约一半（黄绿像素占比 8.7% → 4.0%），Boss 因树皮/叶簇比例不同，占比变化不大。
- 未接入任何第三方素材（PixelFX/PVFX/OpenGameArt 只作参考），原因与许可结论见[开源素材与许可清单](../art/木境开源素材与许可清单.md)。
