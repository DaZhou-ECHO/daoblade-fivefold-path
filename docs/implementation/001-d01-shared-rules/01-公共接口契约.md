# 001 公共接口契约

## 一、权威来源和责任

共享数据：`static/data/rules/legacy-v1.json`。Python读取入口：`shared_rules.py`；前端纯适配器：`DaoBladeRules.createRuntime(config)`。服务端完整存档校验仍是game_rules.validate_state；JS计算和validateLoadout不是服务端权限校验的替代物。

旧玩法数值公式只有前端纯适配器一份实现；Python不额外复制整套逐帧战斗计算。共同样例用于校验两端重叠规则，不能据此声称服务端已经权威验证通关和掉落。

## 二、可调用接口

| 接口 | 输入→输出 | 约束 |
|---|---|---|
| get_ruleset / runtime.config | 无→完整配置 | Python返回副本；JS配置深度冻结 |
| rules_metadata / runtime.metadata | 无→四项契约元数据 | 不包含DB revision |
| default_state / defaultState | 无→独立默认存档 | 每次新对象，字段与旧档一致 |
| element_totals / elementTotals | 有效旧档→五行数值 | 沿用共同基础值与珠等级之和 |
| primary_secondary / primarySecondary | 有效旧档→主、副或空 | 保留并列未定，不伪造历史顺序 |
| validate_loadout / validateLoadout | 旧档→独立出战栏 | 拒绝未学、重复、非法卦路；老档缺省为空栏 |
| calculateStats | 有效旧档→派生战斗属性 | 纯计算，loadout不引用原档；不是存档写入API |
| createProgressionState | 有效旧档→只读节点视图 | 节点有稳定旧适配ID，不持久化新阵盘 |
| createCombatSnapshot | 有效旧档→深度冻结开战配置 | BattleGame实际使用，战斗中不重新计算 |

输入在正式链路中来自服务端校验档或受控试镶副本；公共计算函数不是通用任意JSON验证器。错误规则头和无效出战会抛出可识别异常；后端转换为400错误，未知规则不会静默降级。

## 三、CombatSnapshot形状

```text
contract_version / ruleset_id / schema_version / rules_version
progression: player, inventory, nodes[id], loadout, progress
stats: 当前旧公式结果、独立loadout、totals/depth/mastery/affixes
skills[2]: trigram_id, element, upgraded, element_source
appearance: mode, primary, secondary
```

skills.element_source与appearance.mode目前明确标为legacy-global-primary，保留旧玩法。未来D03独立技能核心元素与主要外观阵式须另建适配器，不能只删掉这个标记后声称已经实现。

player生命/剑意/临时护盾、冷却、位置和怪物状态不在只读stats里；它们属于BattleGame当局可变状态。练功预览也建立独立快照，不回写正式档。

## 四、HTTP契约

- `GET /api/rules`：无需登录，200返回 `{contract, ruleset}`；均为公开游戏规则，无密钥或私人存档。
- `GET /api/state`：沿用现有访客/账号分档，200返回 `{state, revision, contract}`。
- `POST /api/state`：游客仍提交原state；账号仍提交 `{state, revision}`及CSRF；成功信封新增contract，原字段不变。非法规则/结构返回400，账号版本冲突仍409。
- reset及游客导入成功信封也增加contract，不改变其登录、CSRF及覆盖限制。
- 历史state.version=1继续可用。state若显式携带ruleset_id/schema_version/rules_version，则必须与此适配器一致；不会自动给旧数据库加字段。

## 五、后续契约状态

ActionState、BattleEvent和LevelDefinition本轮仅有策划，没有生产级实现。下一步可单独做“动作只读视图→人物渲染消费”，或单独做“稳定关卡锚点”，不能让音效/地图任务临时加入各自版本的公共协议。

涉及完整八卦阵盘与新档时，schema_version和ruleset_id须显式设计。旧适配节点中的legacy_layer仅用于兼容，不是新阵盘必须继续三槽的约束。
