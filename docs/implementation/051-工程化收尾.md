## 行为说明

**会话密钥解析顺序**：`SECRET_KEY` 环境变量 → `instance/session-secret.key`（长度≥32 才复用）→ 生成 `secrets.token_urlsafe(48)` 并写盘（权限尽量设为 0600）。测试显式传入 `SECRET_KEY` 时既不读也不写文件，因此测试环境不受本机文件影响。首次生成会打一条 warning 指向密钥路径。

**API 错误**：路径以 `/api/` 开头或请求体是 JSON 时，`HTTPException` 一律返回 `{"error": 中文提示, "status": code}`；页面请求仍返回 Flask 自带 HTML 错误页。`400/401/403/404/405/409/413/415/429/500` 有固定中文文案，其余状态码回落 `exc.description`。

**健康检查**：`GET /api/health` 执行 `SELECT 1`；成功返回 `status=ok, database=true` 与 `rules_metadata()`（`contract_version/ruleset_id/schema_version/rules_version`），失败返回 `503` 且 `status=degraded, database=false`。旧字段 `game` 保留，原有只读调用兼容。

## 兼容性与风险

- 旧浏览器标签页在服务重启后仍可继续使用会话，因为密钥来自文件而非随机内存值；相反，如果手动删除 `instance/session-secret.key`，所有登录态会失效一次，属预期行为。
- API 错误从 HTML 变为 JSON，前端只读取 `error` 字段，现有 `journey-ui.js`/`save-slots.js` 无需改动，前端回归已覆盖。
- 健康检查在数据库不可用时返回 503，监控或脚本若只判断 200 需要区分两种情况；游戏页面自身不依赖该接口。
- CI 只验证自动化与素材，不包含浏览器实玩、视觉走查与听觉验收。
