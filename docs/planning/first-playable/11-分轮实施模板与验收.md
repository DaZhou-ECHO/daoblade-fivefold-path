本文件是未来人工安排或任务提示词的模板，不是现在自动执行代码、定时运行或推送的授权。每轮只选择 D01–D10 的一个方向及一个可展示小目标。

## 每轮四个关口

| 关口 | 必须回答 |
|---|---|
| 开始 | 当前代码是否已实现？有没有人工修改？依赖与产品决定是否具备？ |
| 设计 | 本轮只拥有哪个行为？其他模块通过什么字段/事件接入？ |
| 验证 | 原问题是否消失？本轮接触的旧流程是否仍可用？哪些仅Mock、哪些实际观察？ |
| 交接 | 下轮能否从仓库复现，不依赖聊天记忆？没有完成的是否继续保留？ |

发现严重回归、存档风险或多人同时修改同一公共文件时，可以暂停本轮内容并先做保护性处理；原因写明。不能把无关重构藏进一次角色或地图优化。

## 初版整体验收矩阵

1. 新玩家：启动→理解操作→推荐选关→完成教学与样板关。
2. 构筑：获得珠子→试配→显示成式/失效原因→保存→进入战斗对比。
3. 存档：退出/重登、旧档读取、双窗口冲突、网络失败、测试档隔离。
4. 关卡：主支路通行、检查点续玩、整关重试、首领奖励只结算一次。
5. 操作：地面/空中/受击/打断/暂停/失焦/退出，旧人物与旧局状态不残留。
6. 表现：双向手剑锚点，敌人前摇可辨；无声音/无震屏/缺素材仍可判断并操作。
7. 五境：用基础配置和不同有效构筑逐关体验；记录时长、死亡位置、卡点及不公平伤害。
8. 交付：在目标 Windows 笔记本按README启动，依赖明确；源代码、资源授权与中文文档对应实际实现。

建议至少邀请两位未参与该关卡制作的试玩者记录一次体验；这是未来验收提案，不是已做的用户测试。以实际记录评价难度，不用“配置了多少敌人/特效”替代可玩性。

## 版本与文档的维护原则

本套策划新增共用规则后，优先更新一份权威契约，再同步受影响方向；不要每天复制整套方案。旧设计文档保留为历史，不与新确认的测试规则混作当前实施依据。

角色 U01–U08 继续作为 D04/D08 的细分任务引用；不能因为总方向增多就删除旧待办或把未制作图层标为完成。新确认的可拆换测试、A完整阵盘、卦位本属五行、人物境界、技能独立元素和外观另选主要阵式，优先于旧冲突方案；只有实际开发并验收后才能把功能状态改为已实现。
