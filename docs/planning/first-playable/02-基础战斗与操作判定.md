# D02 基础战斗与操作判定

状态：策划草案。依赖 D01 的动作和事件约定。核心问题是“玩家按下后发生什么”，与人物画得多精细分开。

## 接续现状

已有移动、跳跃、三段劈砍、正面格挡/完美格挡、反击、短闪避、剑气、Q/E 主动技能、自定义按键与暂停。U01 已补倒地与一次结算，不应重新设计死亡链。后续先验证现有缓冲、打断和阶段，再决定局部调整。

## 初版规则表应回答什么

- 每种动作何时接受输入，何时进入前摇、有效、恢复，何时能衔接下一动作。
- 普攻连按是否缓冲、长按是否重复；格挡松键、跳跃落地、受击打断后的输入如何清理。
- 闪避解决位移，格挡解决正面防守；明确无敌区间、背后攻击和完美格挡窗口，不依靠动作图片猜测。
- 空中攻击、落地、主动技能与格挡同时按下时，采用统一优先级。
- 暂停、失焦、隐藏页面、重试、退出与旧局销毁正确，不出现卡键、迟到命中或重复结果。
- 键盘重绑定与触控操作要走相同动作入口。镜头不能让危险区域长期处于屏幕外。

## 本轮不应混入的内容

人物帧与剑形由 D04 提供；技能尾迹由 D08 提供；声音由 D09 提供。它们读取本方向给出的动作阶段和位置。不能用延长动画来暗改攻击距离、伤害或无敌时长。

## 最小实施路线

1. 先做“动作优先级＋三段连击收招”一条链路，记录当前实际行为。
2. 再做格挡→反击、闪避→恢复、空中→落地三个独立小目标。
3. 之后统一怪物与玩家受击状态的边界；要改数值时单独列平衡任务。

## 验收

新存档基础配置可完成主路；慢按/快按/同时按/松键/失焦均有明确结果；同一攻击不会因帧率不同多次命中；暂停与重试不残留旧输入。真实试玩记录“误触、无响应、无法解释的受击”发生在哪个阶段，不能只以测试通过代表手感合格。


## 本地实施补充：026 持续格挡受击恢复

- 持续按住格挡被受击硬直打断时，硬直期间仍不可防守，结束后只恢复普通正面格挡。
- 不调用新按键的起手逻辑，不重开完美格挡窗口；原伤害、减伤、硬直、无敌时间保持。
- 最后一个键盘/触控来源松开、暂停/失焦清理、退出/死亡均取消恢复；松一个来源不影响另一个仍按住的来源。
- 新的J/L/Q/E/闪避意图取消旧恢复，避免受击后自动格挡吞掉后续动作；攻击结束不会因为旧K仍按住而自行举盾。
- 无持有输入的主动技能防守不自动延续。受击中首次按K不作为缓冲，不额外获得弹反。
- 实施与证据见[026任务](../../agents/026-d02-held-guard/TASK.md)，不等同于五境全流程平衡验收。


## 本地实施补充：028 初次普通格挡短缓冲

此条更新026关于“受击中首次按K不缓冲”的局部选择；026已举盾后受击恢复仍保持。

- 在施法、受击、闪避或不可取消的劈砍末段按下K，记录0.18秒普通格挡意图。仍需持有输入，超时后不会自动举盾。
- 按原动作取消规则判断，第三段劈砍必须结束；不缩短硬直或扩大取消窗口。
- 窗口内恢复可行动后，只进入普通格挡，不重开完美格挡，不刷新弹反锁定；立即合法的新K仍使用原完美格挡窗口。
- 最后来源松手、暂停/失焦/销毁/死亡、新J/L/Q/E/闪避意图或新一次受击取消等待；多来源释放保持独立。
- 实施证据见[028任务](../../agents/028-d02-guard-input-buffer/TASK.md)，水境首领实际胜利另验。


## 030持续格挡规则更新

正式水境实玩确认：K与短按Q/E不同，玩家仍按住时，不应因0.18秒过期而永久丢失普通防守。此条覆盖028关于K等待过期的局部选择。

- 首次K被原动作限制拒绝时，只要输入来源仍持有，就等原动作许可后进入普通格挡；第三段不可提前取消、受击硬直不能缩短。
- 等待时再受击，保留该持续防守意图，硬直结束恢复普通挡；不自动重开弹反。新一次立即合法K仍按原窗口。
- 最后输入来源松开、暂停/失焦/死亡/销毁、新J/L/Q/E/闪避意图均取消，不能在松手后自动举盾。
- Q/E仍使用0.18秒一次性短缓冲，不延长。
- 证据见[030](../../agents/030-d06-five-realm-browser/TASK.md)。
